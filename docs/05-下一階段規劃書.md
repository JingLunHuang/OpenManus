## 2. 工作項目

### W1 · 真實模型「有記憶／無記憶」對照實驗（核心，最先做）

**動機**：這是 02／03／04 三份文件一致列為「下一步最該補的實驗」的項目。面試時最容易被追問的就是：
「你說記憶有用，數據呢？」目前只能回答「離線示範」，說服力有限。

**設計要點**：

- 實驗基建放在 `scripts/experiments/`：固定任務集、執行紀錄彙總、成本結算，一個命令可重現；
- 任務集 ≥ 12 題，涵蓋 `web_query`／`research`／`coding` 三種模式；其中 ≥ 6 題是**同一站點的重複任務**（記憶能發揮作用的前提）；
- 對照組：`memory off`（不掛 MemoryHook）與 `memory on`（載入目前 RSI 版本）；每題各跑 3 次，成功率取多數；
- 量測：成功率、步數、模型呼叫數、token 成本（含快取命中折扣）、查證輪數與放行率、牆鐘時間；
- 成本控制：實驗總預算上限 ＋ 每次執行 `budget` 與 token 雙重上限，超限即中止並記錄。

**驗收**：

- `experiments/report.md`：兩組成功率／成本對照表、逐題明細、誠實的限制（樣本小、不宣稱統計顯著）；
- 實驗紀錄（`events.jsonl`）留存，任何人可用 `lingxi replay` 復盤。

**風險**：需要真實 API 與費用；真實站點若反爬升級，退回離線夾具頁並在報告中註明。

### W2 · 端到端受保護評測套件（真實模型、預算對等）

**動機**：RSI 目前評測的是元件級能力；「技能升格為手冊」這類改變，需要端到端證據才算数。

**設計要點**：

- `lingxi/evolve/protected/` 新增 `e2e` 套件：4–6 個固定小任務（離線夾具 ＋ 可公開存取的真實站點混合）；
- 預算對等：基準版本與候選版本使用相同基礎預算與同一任務集，比較成功率與有效成本；
- 沿用三道門：改進器看不到評測集、內容雜湊即評測週期、查詢預算上限。

**驗收**：`lingxi evolve round --with-e2e` 完整跑完一輪（含接受或拒絕候選），e2e 結果寫入自主歸屬帳本。

**注意**：成本較高，排在 W1 基建完成之後（兩者共用任務集與成本結算）。

### W3 · 查證自動第二來源檢索

**動機**：目前「○ 單一來源」的關鍵數字，查證員只做標註，模型補不補查全憑自覺。

**設計要點**：

- `finish` 時查證員額外輸出「單一來源的關鍵數字」清單（最多 3 條，依重要性排序）；
- 內核對每條自動發起一次 `web_search` ＋ `web_read`（上限 2 步），結果寫回發現板後再判定；
- 以 `[verify] auto_second_source` 控制開關與適用的任務模式。

**驗收**：離線測試復刻「單一來源 → 自動檢索 → 升為多方印證／仍單一來源被標註」；真實任務至少 1 例因此改變查證結果。

### W4 · 多標籤並行檢索

**動機**：`research` 模式做多源印證的前提；也是路線圖遺留項。

**設計要點**：

- 瀏覽器會話支援多分頁，`web_open`／`web_search` 可指定新開分頁；
- 快照與 `data-lx-id` 命名空間按分頁隔離，本步簡報標明當前分頁；
- 主迴圈維持單一動作序列（不讓模型同時操作兩個分頁），避免觀察歸屬模糊。

**驗收**：離線夾具測試兩個分頁並存；真實模型完成一次「分別查 A、B 兩站再合併」的調研任務。

### W5 · 穩定性迴歸看板

**動機**：把「穩定性」量化（[03 §4](03-GitHub差異化分析.md)），讓「同一任務跑三次都成功」成為可展示的數字。

**設計要點**：

- `lingxi stats`：彙總 `runs/` 下所有執行，按任務分組輸出成功率、步數中位數、token、KV 重用率；
- Web 介面「紀錄」頁增加按任務聚合的視圖。

**驗收**：同一任務 ≥ 3 次執行紀錄時看板可顯示數字；直接复用 W1 的實驗產出。

### W6 · 作品集收尾（選配，不阻塞以上）

- README 增加英文摘要段；
- 重跑「乾淨 clone → `lingxi doctor` → 測試全綠」流程確認；
- 準備 3 分鐘示範講稿（搭配現有 Web 介面截圖）。

## 3. 執行順序與里程碑

| 里程碑 | 內容 | 完成定義 |
|---|---|---|
| M1 | W1 實驗基建 ＋ 任務集 | `scripts/experiments/` 可先用假模型乾跑 |
| M2 | W1 真實模型執行與報告 | `experiments/report.md` 產出，成本在上限內 |
| M3 | W3 ＋ W4（可並行） | 離線測試全綠 |
| M4 | W2（依賴 M1 基建） | 完成一輪含 e2e 的 RSI 紀錄 |
| M5 | W5 ＋ W6 收尾 | 看板與文件更新 |

建議順序 **M1 → M2 → M3 → M4 → M5**：W1 的基建被 W2 复用；W3／W4 不碰實驗路徑，可與 M2 之後的工作並行。

## 4. 成本與風險管理

- **成本上限**：M2 開跑前先定總預算上限（數字待你決定）；每次執行另有 `budget` 與 `max_tokens` 雙重護欄；
- **站點風險**：真實站點反爬升級時退回離線夾具頁做對照，並在報告中誠實註明；
- **結果風險**：若實驗結果是「記憶沒有提升成功率」，照實寫——本專案的價值在機制與量測可重現，不在數字好看。

## 5. 不做的事（範圍管理）

- 不引入新的代理框架、不改 Kernel 主迴圈結構；
- 不宣稱小樣本實驗具有統計顯著性；
- 不做雲端服務化，一切本地可跑。
